# Infra Jejak — Prototype Build

Community-driven road infrastructure safety & monitoring app (Flutter),
built for BMIT2073 Mobile Application Development, supporting **SDG 9**.

## ⚠️ Read this first — one required setup step

This zip contains the **full Flutter source code** (`lib/`, `assets/`,
`pubspec.yaml`) but **not** the `android/`/`ios/` platform folders. Those
are normally machine-generated by the Flutter CLI to exactly match your
installed Flutter SDK version — shipping pre-built ones risks a version
mismatch that causes confusing build failures on your machine. Generating
them yourself is safer and is standard practice.

**Before opening in Android Studio, run this once:**

```bash
# macOS/Linux
chmod +x setup.sh && ./setup.sh

# Windows
setup.bat
```

This runs `flutter create .` (adds the missing platform folders — it will
**not** touch your existing `lib/` or `pubspec.yaml`) followed by
`flutter pub get`. After that, the project is a completely normal,
runnable Flutter project.

## What's in this build

The full core cycle from the project brief is implemented and working:
**Discover → Report → Validate → Verify → Track → Resolve**

- **Main Map** — OpenStreetMap-based interactive map (`flutter_map`),
  showing official JKR blackspots and community hazards with distinct
  markers, legend, filters (by source/category/resolved), current location.
- **Hazard Details** — full info, clearly labelled Official vs Community
  source, Confirm/Dispute buttons (community reports only), and **live
  district population context from OpenDOSM** (see below).
- **Report Hazard** — form with hazard type, severity, GPS (editable),
  camera/gallery photo, district, description.
- **Community Reports** — searchable list of all community submissions.
- **My Reports / Tracking** — a user's own reports with a status timeline
  that only shows stages actually reached.
- **Admin Dashboard** — stats + Pending Review / High Severity / Highly
  Validated / Recent / Resolved queues.
- **Admin Report Review** — full report view with Acknowledge / Mark
  Repairing / Mark Resolved / Reject actions.
- **Auth** — login/register screens.

## Data sources (real, verified)

| Data | Storage | Type | Source |
|---|---|---|---|
| JKR blackspots | **SQLite** (local) | Static, bundled | Sample — see note below |
| District population | Live API call | Dynamic, real-time | **OpenDOSM** (`api.data.gov.my`), verified live endpoint |
| Community reports, validations, status history | **Firebase Firestore** (remote) | Dynamic | User-generated |

### JKR blackspot dataset — important honesty note

**data.gov.my does not currently publish a point-level (lat/long) JKR
blackspot dataset** — only aggregate accident statistics tables (counts
by state/type/year, no coordinates). This was verified by searching
data.gov.my directly. So `assets/data/jkr_blackspots.json` is clearly
labelled in its own `_meta.source` field as a **manually compiled sample**
(8 Klang Valley locations, in the correct schema a real dataset would
use) — not a false claim of an official feed.

To replace it with something more defensible for submission:
1. **Best option:** if your group can obtain real geocoded blackspot data
   (from a state JKR office, a FOI request, or MIROS), run it through
   `data_prep/prepare_jkr_data.py` — it cleans, deduplicates, validates
   coordinates against Malaysia's bounding box, and writes the exact JSON
   this app reads.
2. **Also legitimate:** data.gov.my *does* have real, downloadable accident
   statistics (search "kemalangan jalan raya") — no coordinates, but
   genuine government data usable for a stats/context screen.
3. **What we actually built instead:** a second, verified-live government
   data source — see below.

### District population context (OpenDOSM) — genuinely live

`lib/services/opendosm_service.dart` calls the real, public data.gov.my
Open API:

```
GET https://api.data.gov.my/data-catalogue?id=population_district
    &filter=<district>@district,overall@sex,overall@age,overall@ethnicity
```

This is DOSM's (Department of Statistics Malaysia) **Population Table:
Administrative Districts** dataset — live, current, CC BY 4.0 licensed.
Unlike the JKR sample, this is not a bundled file: the app makes a real
HTTP request every time a hazard's district page is opened, and shows the
district's current population as context on the Hazard Details screen.
This satisfies the assignment's "real-time or static data from Malaysian
Government open-data platforms" requirement with a source you can verify
yourself at https://open.dosm.gov.my/data-catalogue/population_district.

To see it: report a hazard and fill in the optional "District" field
(e.g. "Petaling", "Gombak", "Kuala Lumpur"), or open one of the 3 seeded
demo reports, which already have districts attached.

## Local vs remote database — both fully working

| | Local (SQLite) | Remote (Firebase) |
|---|---|---|
| **What it stores** | Prepared JKR blackspots | Community reports, validations, status history, user accounts |
| **Works out of the box?** | **Yes** — seeded from the bundled JSON asset on first launch, zero setup | **Yes** — via an in-memory demo backend until you connect a real Firebase project (see below) |
| **Code** | `lib/database/db_helper.dart` | `lib/services/{auth,firestore,storage}_service.dart` |

**The whole app runs and demos completely today**, including the "remote"
storage — reports get submitted, validated, tracked, and admin-reviewed
all in a session-persistent in-memory store
(`lib/services/mock_data_store.dart`), controlled by
`AppConfig.useMockBackend`. The moment you connect a real Firebase
project (steps below), `main.dart` detects it automatically and every
screen switches to real Firestore/Auth/Storage — no code changes needed.

### Connecting real Firebase (optional but recommended before final submission)

1. Create a project at console.firebase.google.com.
2. Add an Android app — package name must match `applicationId` in
   `android/app/build.gradle` (only exists after running `setup.sh`).
3. Download `google-services.json` into `android/app/`.
4. In `android/build.gradle` (project-level), add
   `classpath 'com.google.gms:google-services:4.4.2'` to `dependencies`.
   In `android/app/build.gradle`, add
   `apply plugin: 'com.google.gms.google-services'` at the bottom.
5. In the Firebase console: **Authentication** → enable Email/Password.
   **Firestore Database** → create (test mode to start). **Storage** →
   get started (test mode to start).
6. `flutter run`. If you don't see "Firebase not configured yet" in the
   debug console, it connected — you're now on real Firebase.

Also double check `android/app/src/main/AndroidManifest.xml` (generated
by `setup.sh`) includes:
```xml
<uses-permission android:name="android.permission.INTERNET" />
<uses-permission android:name="android.permission.ACCESS_FINE_LOCATION" />
<uses-permission android:name="android.permission.ACCESS_COARSE_LOCATION" />
```
These are needed for Firebase/OpenDOSM/map tiles and GPS respectively.

#### Firestore security rules (starting point — tighten before submission)

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /users/{userId} {
      allow read: if request.auth != null;
      allow write: if request.auth != null && request.auth.uid == userId;
    }
    match /reports/{reportId} {
      allow read: if true;
      allow create: if request.auth != null;
      allow update: if request.auth != null; // tighten: admin-only for status changes
    }
    match /validations/{validationId} {
      allow read: if request.auth != null;
      allow create: if request.auth != null;
    }
    match /status_history/{entryId} {
      allow read: if request.auth != null;
      allow create: if request.auth != null;
    }
  }
}
```

## What's intentionally NOT built (see Section 29 of the brief)

No AI image recognition, chat, push notifications, gamification, or
government-agency integration — kept out to stay within a realistic
university-project scope. These are documented as future improvements.
